## What's Changed

- **Fixed Mole failing to install after a `.pkg`/Self Service deployment.** The package's postinstall script ran Mole's installer and launched MacMoleManager as the logged-in user, but with root's `HOME` (`/var/root`) still in the environment. Mole's installer couldn't write `~/.config` or read `~/.bash_profile`, so it wasn't pre-installed, and the in-app "Set Up Mole" flow then failed the same way with `Permission denied`. The postinstall now sets `HOME`, `USER`, and `LOGNAME` explicitly for the console user.
- **MacMoleManager now corrects a bad inherited `HOME` at launch.** If an installer, MDM script, or other tool starts the app with the wrong home directory, the app resets it from the user's account record so Mole, its installer, and Homebrew all write to the right place.
